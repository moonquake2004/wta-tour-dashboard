# WTA 女子网球数据看板

**在线访问：** <https://moonquake2004.github.io/wta-tour-dashboard/>

一个独立、开源的 **Hologic WTA 巡回赛** 数据看板。

排名、球员档案、生涯纪录、交手记录、赛程与赛季统计——所有数字都直接来自
**WTA 官方数据接口**，重新组织成一个快速、无依赖的静态网站。

> **数据快照**：排名截至 **2026 年 8 月 31 日** · 300 位排名球员 · 300 份球员档案
> · 2025–2026 赛季 222 项赛事。本站与 WTA 无隶属关系。

---

## 项目定位

WTA 官网的数据本身很权威，但它的组织方式是为"看新闻"服务的，不是为"查数据"服务的。
本项目把驱动 `wtatennis.com` 的同一套公开 JSON 接口取下来、归一化，再呈现成一个数据工具：

- 完整可排序、可筛选的排名表，含每周名次变动；
- 球员页整合生涯档案、赛季发球/接发数据、五年排名曲线和完整比赛记录；
- 交手分析器，覆盖已存比赛窗口内两位球员的每一场交锋；
- 赛程日历，含场地类型、奖金与冠军；
- 12 个赛季排行榜，全部由官方已发布的字段计算得出。

没有任何数字是估算、建模或从 HTML 里"猜"出来的。官方接口里没有的字段，本站就不会显示。

## 数据来源

全部来自 `wtatennis.com` 背后的公开 JSON 接口：

| 接口 | 用途 |
| --- | --- |
| `GET /tennis/players/ranked` | 官方单打排名表（`type=rankSingles`） |
| `GET /tennis/players/{id}/detailed` | 生涯档案：胜负、冠军数、最高排名、奖金 |
| `GET /tennis/players/{id}/year/{season}` | 赛季发球与接发统计 |
| `GET /tennis/players/{id}/ranking` | 单打/双打逐周排名历史 |
| `GET /tennis/players/{id}/matches` | 完整比赛记录 |
| `GET /tennis/players/{id}/headtohead/{opp}` | 生涯交手记录与每一场比赛 |
| `GET /tennis/tournaments` | 赛程、签表、场地、奖金、冠军 |

### 两个决定架构的约束

1. **接口每页最多 100 行**，排名深度必须翻页获取。
2. **接口拒绝跨域浏览器请求**：只要 `Origin` 不是 `wtatennis.com`，一律返回 `HTTP 403`。
   因此网站**无法**在浏览器里直接调用它——包括交手记录在内的所有数据，都在构建时预计算成静态 JSON。

## 本地开发

需要 **Node.js 20+**，没有任何 npm 依赖。

```bash
# 1. 由 site/ + data/ 组装出可发布站点
node scripts/site.mjs

# 2. 本地预览（ES 模块必须走 HTTP，file:// 不行）
node scripts/serve.mjs            # http://127.0.0.1:4173
```

改前端时可以直接服务 `site/`，它会去读 `../data`：

```bash
WTA_SERVE=site node scripts/serve.mjs
```

### 刷新数据

```bash
# 只刷排名 —— 2 次接口调用 + 派生聚合，约 30 秒
node scripts/refresh-rankings.mjs

# 全量：排名、300 份档案、比赛记录、赛程、交手索引，约 12 分钟
node scripts/build.mjs

# 部分刷新
node scripts/build.mjs --skip-players --skip-matches
```

抓取器刻意保持"有礼貌"：并发受限、请求间隔下限、指数退避重试。请沿用默认值。

## 部署

站点通过 **GitHub Pages** 发布 `docs/` 目录：

1. `node scripts/site.mjs` 生成 `docs/`；
2. 提交并推送到默认分支；
3. 在 **Settings → Pages** 中选择 *Deploy from a branch*，分支 `main`、目录 `/docs`。

`.github/workflows/refresh.yml` 会在每周一（WTA 发布新榜单时）自动刷新排名数据。

### 为什么用 hash 路由

前端是单 HTML 入口 + `#/route` 形式的 URL。GitHub Pages 只提供静态文件，
hash 路由可以做到深链可用、零服务端配置、无需 404 规则。

## 数据口径说明

- **排名周期**：WTA 每周一发布排名。站内展示的日期是该快照所属的那一周，而不是下载日期。
- **名次变动**：箭头对比的是官方表中的"与上周相比"，与原表一致。
- **赛季胜负**：由官方比赛记录统计，剔除没有比分的轮空/弃权，因此能与官方赛季战绩对齐
  （例如萨巴伦卡 2026 赛季 40 胜 8 负）。
- **`winner` 字段语义**：在比赛数据里，`winner` 是**负方**的位置编号
  （`1` 表示 `player_1` 获胜）。这一结论已用公开赛果交叉验证。
- **ACE 球**：依赖各赛场的线审技术，跨赛事不完全可比。
- **生涯数据**：最高排名、冠军数、奖金均逐字取自 WTA 档案，球员页会显示官方"最后更新"日期。
